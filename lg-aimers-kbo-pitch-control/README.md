# ⚾ KBO 투구 제구 성공 확률 예측

**LG Aimers 9기 · Phase 2 온라인 해커톤 (주최 LG AI연구원 / 주관 데이콘)**

투구 직전까지 알 수 있는 정보(볼카운트·주자 상황·선수 특성·과거 이력)만으로 각 투구가 **제구에 성공할 확률**을 예측하는 모델입니다.
결과 CSV가 아니라 **추론 코드와 모델을 통째로 제출**하면 평가 서버가 실행해 채점하는 *코드 제출 대회*였습니다.

| | |
|---|---|
| **Public Score** | **793** (수료 기준 = 운영진 베이스라인 점수 549.51) |
| 평가지표 | Brier Skill Score — `100000 × (1 − Brier / r(1−r))` |
| 학습 데이터 | KBO 2019~2024 시즌, 1,475,092 투구 |
| 평가 데이터 | 2025 시즌 245,789 투구 (비공개, 서버에서만 실행) |
| 모델 | LightGBM 3-seed 평균 + 시즌 드리프트 보정 |
| 제출 용량 / 추론 시간 | 약 1.8MB / 245,789행 약 21초 (로컬 1 vCPU 모의 측정, 제한 10분) |

> 💡 이 문제는 **신호가 매우 약합니다.** 793점은 "항상 평균값만 찍는 모델" 대비 Brier를 약 0.8% 낮춘 것입니다.
> 그래서 점수를 짜내는 것보다 **미래 시즌에서 무너지지 않는 모델**을 만드는 데 집중했습니다.

## 1. 핵심 설계 결정

### ① 검증은 "과거 → 미래"로만 (rolling-origin)
평가 대상이 학습 기간 이후인 **2025 시즌**이라 무작위 분할은 의미가 없습니다.
`2019~2023 → 2024`, `2019~2022 → 2023` 두 폴드로 검증했습니다. 한 폴드만 봤다면 아래 ③의 문제를 놓쳤을 겁니다.

### ② EDA에서 확인한 신호 → 피처로 변환
| 관찰 | 근거 | 반영 |
|---|---|---|
| **3볼 카운트에서 성공률 하락** | 3볼 0.4996~0.5073 vs 1스트라이크·0볼 0.5341 | `count_diff`, `walk_threat` |
| **투수·타자 손 조합** | (투수1, 타자1)만 0.4909, 나머지 0.5221~0.5375 | `hand_combo` |
| **과거 성공률의 평균 회귀** | 과거 성공률 하위 10% 구간: 피처 0.434 → 실제 0.457 / 상위 10%: 0.650 → 0.612 | 경험적 베이즈 축소 `pitcher_rate_smoothed` |

과거 성공률은 투구 수가 적은 투수일수록 극단값이 나와 **그대로 쓰면 과신**합니다.
그래서 `(성공 수 + 0.5236 × 200) / (투구 수 + 200)` 로 리그 평균 쪽으로 당긴 값을 추가했습니다.
(개발 중 확인한 모델 중요도에서 축소 버전이 원본 `asof_pitcher_success_rate`보다 높게 나왔습니다: 10.7% vs 7.3%)

### ③ 중요도 1위 피처 `game_type`을 **제거**
모델 중요도 1위(약 16%)였지만, 연도별로 쪼개 보니 **2023년에 관계가 뒤집혔습니다.**

<p><img src="docs/images/game_type_flip.png" width="48%"></p>

| 검증 폴드 | game_type 포함 | game_type 제외 |
|---|---|---|
| val = 2023 | **−1,472.9** | −146.3 |
| val = 2024 | 662.3 | 601.0 |

2024 폴드에서는 +61점 이득이지만 2023 폴드에서는 −1,327점 손실입니다. 2025년에 또 바뀌면 점수가 무너지는 구조라,
**작은 이득보다 큰 손실을 피하는 쪽**을 택해 제거했습니다.

### ④ 시즌 드리프트 보정 (DELTA)
리그 평균 제구 성공률이 해마다 내려갑니다. Brier Skill Score는 **예측 평균이 실제 평균에서 벗어나는 것만으로도 감점**됩니다.

<p><img src="docs/images/season_drift.png" width="48%"></p>

- 학습 데이터의 시즌별 평균에 직선을 맞춰 **2025 평균을 0.4747로 외삽** (기울기 −0.0141/년)
- 참조 모델의 2024 예측 평균과의 차이를 **로짓 상수 DELTA(−0.0988)** 로 저장, 추론 때 모든 예측에 더함
- val=2024 기준 **619.4 → 673.6** (평균을 정답으로 맞춘 이론상 상한 695.9)

> **대회 규칙 준수**: DELTA는 *학습 데이터만으로 학습 시점에 확정된 상수*(`config.json`)입니다.
> 평가 데이터의 다른 행이나 전체 분포를 전혀 참조하지 않고, 각 행에 독립적으로 적용됩니다.

`season`을 피처에서 빼면 오히려 크게 나빠졌습니다 (개발 로그: 662.3 → 230.8). 트리 모델이 처음 보는 2025를
"가장 최근 시즌(2024)의 분기"로 처리하는 것이 단조 하락 추세에서는 유리하게 작동하기 때문으로 해석했습니다.

### ⑤ 3-seed 앙상블
신호가 약할수록 시드 하나의 우연이 결과를 좌우합니다. 시드 3개 평균으로 분산을 줄였습니다.

## 2. 시도했지만 채택하지 않은 것 (음의 결과도 기록)

| 시도 | 결과 | 판단 |
|---|---|---|
| 피처 14개 추가 (shrinkage 확장, 최근 폼 이탈도, 매치업, 구종 엔트로피 등) | 판별력 671.7 → 650.7 (val 2024) | 과적합, 미채택 |
| 피처 축소 (상위 40/30/22/15개만) | 657 / 634 / 611 / 600 (개발 로그) | 51개가 최적 |
| Isotonic 확률 보정 | 639.6 → 512.0 (개발 로그) | 시즌 간 분포 이동으로 오히려 악화 |
| Logistic Regression / 앙상블 | 0.0 / 156.5 (개발 로그) | 비선형 상호작용 못 잡음, 미채택 |
| 최근 시즌 가중 / 최근 3시즌만 학습 | 227.7 / 162.5 (개발 로그) | 데이터를 줄이면 신호가 더 약해짐 |
| `trackman_history.csv` 활용 | 불가 | 투수 ID 체계가 다르고(`pitcher_id` ≠ `pitcher_trackman_id`), 투구 수 분포상 같은 경기 집합도 아님 → 억지 매칭은 노이즈 |

### 정규화 강화 실험 (제출본에는 **미반영**)
잎 노드 최소 샘플 수(`min_child_samples`)를 키우면 확률 추정이 안정되어 판별력이 올랐습니다.

| 설정 | val 2023 | val 2024 |
|---|---|---|
| 제출본 (mcs=200) | −82.2 | 671.7 |
| mcs=2000, L2=100 | −54.3 | 715.1 |
| mcs=10000, L2=100 | −54.1 | 737.3 |

2023 폴드는 개선 폭이 작고 **여전히 음수**입니다. 후속 개선 방향으로만 남겨둡니다.

> ※ 위 수치는 개발 중 전체 데이터로 측정한 값입니다. `analysis/experiments.py`는 같은 실험을 정리한 스크립트이며,
> 이 저장소를 만들 때는 5% 샘플로 전 실험의 동작을 확인하고 정규화 실험의 2023 폴드(위 표)만 전체 데이터로 다시 돌렸습니다.
> 실행 환경(스레드 수 등)에 따라 소수점 이하 차이가 있을 수 있습니다. "(개발 로그)" 표시 항목은 저장소 스크립트에 포함되어 있지 않습니다.

## 3. 제출 환경 호환성 (엔지니어링 포인트)

코드 제출 대회는 **실행 중 에러가 나면 하루 5회뿐인 제출 기회가 차감**됩니다. 제출 직전 서버 사양과 대조해 두 가지 위험을 찾아 고쳤습니다.

| 문제 | 원인 | 해결 |
|---|---|---|
| **모델 로드 실패 위험** | 개발 환경(Python 3.12, numpy 2.x)에서 만든 pickle은 서버(Python 3.11, numpy 1.26, pandas 2.0.3)에서 모듈 경로가 달라 로드 불가 | pickle/joblib 폐기 → **LightGBM 네이티브 텍스트 포맷(.txt)** 으로 저장. 변경 전후 예측값이 비트 단위로 동일함을 확인 |
| **설치 충돌 위험** | requirements.txt의 pandas·scikit-learn 버전이 서버 기본 설치 버전과 다름 | 서버에 없는 `lightgbm==4.7.0` **한 줄만** 남김 |
| 미생성 시 제출 오류 | 모델 로드 등에서 예외 발생 가능 | 어떤 예외가 나도 상수(0.4747)로 `submission.csv` 생성하는 **fallback** (모델 파일을 일부러 지워 테스트) |
| 학습-추론 피처 불일치 | 두 곳에 피처 코드를 따로 쓰면 어긋남 | `train.py`가 `submission/script.py`의 `build_features()`를 **그대로 import**해 같은 함수를 사용 |

또한 `train.py`로 다시 학습한 모델 3개가 제출한 모델 파일과 **md5 해시까지 완전히 일치**함을 확인했습니다
(동일 환경: Python 3.12, LightGBM 4.7.0, 1 vCPU).

## 5. 재현 방법

```bash
git clone https://github.com/<GitHub-ID>/lg-aimers-kbo-pitch-control.git
cd lg-aimers-kbo-pitch-control
pip install -r requirements-dev.txt

# 1) data/ 에 데이콘 대회 데이터(train.csv 등)를 직접 내려받아 넣는다
# 2) EDA 그림 생성
python analysis/eda.py
# 3) 학습 → submission/model/ 갱신
python train.py
# 4) 검증 실험 (예: game_type 제거 근거) / 빠른 동작 확인은 --sample 0.1
python analysis/experiments.py --exp gametype
# 5) 로컬 추론 테스트 (서버가 하는 일을 그대로 흉내)
cd submission && mkdir -p data && cp ../data/test.csv ../data/sample_submission.csv data/
python script.py            # → output/submission.csv
# 6) 제출용 zip (최상위에 model/, script.py, requirements.txt 만 있어야 함)
zip -r ../submit.zip model script.py requirements.txt
```

## 6. 한계와 배운 점

**한계**
- **DELTA는 "2025년에도 하락 추세가 이어진다"는 가정**에 기댑니다. 반등하면 오히려 손실입니다 (평균이 0.01 어긋나면 약 40점, 0.03 어긋나면 약 360점 손실).
- 2023 폴드에서는 **모든 모델이 상수 예측보다 나빴습니다.** 레짐이 바뀌는 해에는 이 접근이 통하지 않을 수 있습니다.
- 정규화 강화 모델(위 표)은 검증만 하고 제출에 반영하지 못했습니다.
- `subsample=0.8`은 `subsample_freq=0`이라 **실제로는 행 샘플링이 적용되지 않았습니다.** (시드 간 차이는 열 샘플링에서만 생김. 제출본 재현을 위해 그대로 둠)
- Trackman 릴리스 포인트 같은 제구력의 직접 지표는 데이터 구조상 활용하지 못했습니다.

**배운 점**
1. 한 번의 검증 결과를 믿지 않기 — 폴드를 하나 더 돌렸을 때 가장 중요한 피처의 문제가 드러났습니다.
2. 중요도가 높다고 좋은 피처가 아니다 — **시간에 따라 안정적인지**가 먼저입니다.
3. 약한 신호에서는 복잡도를 올리면 오히려 나빠지고, 규제를 강화하면 좋아졌습니다.
4. 모델 성능만큼 **실행 환경 호환성·실패 설계**가 중요했습니다. 이는 배포 엔지니어링과 같은 문제였습니다.
